prometheus 错误告警 kube-scheduler TargetDown

发表于 2025-09-16 分类于 prometheus 阅读次数：

问题概述

在 Rancher Monitoring 中看到 kube-scheduler TargetDown 告警，并且相关指标为 0：

环境如下：

Env Version
Rancher 2.9.2
monitoring rancher-monitoring-104.1.1_up57.0.3

  1. 检查 Rancher Monitoring 正常使用的 kube-scheduler 抓取链路：

返回结果如下，可以看到，通过 pushprox-kube-scheduler-client 采集的 kube-scheduler 指标是正常的。

  1. 由于告警中的 service 是 rancher-monitoring-kube-scheduler，而正常抓取链路中的 service 是 pushprox-kube-scheduler-client，继续导出所有 ServiceMonitor，查找异常抓取目标来源：

最终找到如下 ServiceMonitor：

这个 ServiceMonitor 抓取 kube-scheduler 的 10259 端口。RKE2 新版本中 Rancher Monitoring 默认通过 pushprox-kube-scheduler-client 获取 kube-scheduler 指标，因此这里的 ServiceMonitor 不应该再启用。

问题原因

RKE2 新版本的 Rancher Monitoring 使用 .rke2Scheduler.enabled=true 通过 pushprox-kube-scheduler-client 采集 kube-scheduler 指标。

如果同时启用了 .kubeScheduler.enabled=true，导致 chart 创建了旧的 rancher-monitoring-kube-scheduler ServiceMonitor。该 ServiceMonitor 直接访问 kube-system 下 kube-scheduler 的 10259 端口，默认情况下无法正常访问，所以 Prometheus 里出现了 TargetDown。

实际 kube-scheduler Pod 和 pushprox-kube-scheduler-client 抓取链路都是正常的，因此这是错误抓取目标引起的误报。

解决方法
